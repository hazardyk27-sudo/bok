# Blackjack operating notes

## Ownership
- Canonical development branch: `feature/blackjack`.
- Owned roots: `artifacts/cascade-8/src/blackjack`, `artifacts/api-server/src/blackjack`, `lib/db/src/schema/blackjack.ts`.
- Shared route mounting, shared wallet/session primitives, schema aggregation, package files, preview infrastructure and promotion machinery remain platform-owned.
- Replit remains a preview/runtime consumer on `integration/replit-preview`; normal Blackjack source development happens on `feature/blackjack` only.

## Product direction
- Single-player blackjack table with exactly five seats. The same player may occupy and play any subset of 1–5 seats simultaneously.
- Desktop visual target is the approved 16:9 premium live-casino mockup: dark green felt, dark leather rail, restrained gold trim, dealer centered behind the table, five seat arc, compact top HUD and integrated bottom betting/action console.
- Mobile will preserve the same table identity in portrait rather than becoming a generic control dashboard.
- `TABLE MIN` exists. There is no `TABLE MAX` label or configured table maximum; the natural affordability ceiling is the player's available shared wallet balance.
- Pre-deal `X2 BET` doubles the selected seat's wager and is distinct from in-round Blackjack `DOUBLE`/double-down.
- Pre-deal controls must support chip placement, last-chip undo, clearing a selected wager, and clear seat state feedback.
- Empty seats expose a clear `TAKE SEAT` / `TAP TO SIT` affordance. Occupied, selected, bet-ready and in-round states are visually distinct.
- Rules baseline: 6-deck shoe, ~75% cut-card reshuffle after a completed round, dealer hits soft 17, Blackjack pays 3:2, normal win 1:1, push returns stake, insurance pays 2:1, normal split hands may reach four hands, DAS is enabled, and split Aces receive one card each with no resplit/DAS.
- The shared `shared_wallets` row and root-scoped `game_session` remain the only live wallet/session authorities; Blackjack never creates an independent spendable wallet.

## Current milestones
- 2026-10-08 — Part 10A server-authoritative round API foundation complete — Blackjack-owned API modules now hold session-scoped shoe, round, roundId and monotonic revision state in the backend. `GET /blackjack/state` returns a no-store public snapshot and `POST /blackjack/action` accepts only intent (`deal/hit/stand/double/split/insurance/declineInsurance/next`) plus `expectedRevision`; DEAL accepts only validated seat+wager input. The backend injects its own crypto-backed RNG, creates/deals the shoe, executes all round mutations, rejects stale revisions, derives allowed actions, and never exposes the shoe order. Dealer hole-card data and dealer-Blackjack truth are redacted from snapshots until the round is complete, including throughout insurance. Regression coverage documents session isolation, server-owned deal order/public redaction, stale-revision rejection, hidden dealer Blackjack through insurance, input validation and the absence of a configured table maximum. A typed `serverContract.ts` and browser `serverApi.ts` transport adapter are ready. Shared `/api` router mounting remains platform-owned and was intentionally not changed on `feature/blackjack`; therefore the current visual mount is not yet cut over from its local demo engine to the new API until central integration mounts the router. Wallet reservation/debit/credit remains Part 10B; persistence/idempotency/reconnect remains Part 11.
- 2026-10-08 — Part 9 INSURANCE complete — dealer Ace upcard now enters a dedicated `insurance` phase before any player action or hole-card reveal. Each participating initial hand is offered insurance in deterministic seat order; accepted insurance is exactly half the main wager and remains a separate side-bet ledger (`insuranceWager`, `insuranceReturnAmount`, `insuranceNetAmount`) rather than being merged into main-hand settlement. After the final decision, the dealer peek resolves: dealer Blackjack pays accepted insurance at 2:1 profit (3x stake returned) and immediately settles the main round; no dealer Blackjack loses accepted insurance and continues into the first playable hand. Declining insurance carries zero stake/loss. An already-settled insurance side bet is preserved on only one descendant if the main hand later splits, preventing accidental duplication. The UI hides the dealer hole card throughout the insurance decision phase, exposes `INSURANCE / NO INSURANCE`, shows the required half-wager amount, includes placed insurance in live TOTAL BET, marks the active mobile seat as `INS`, and renders insurance side-bet status independently from the main-hand result. Regression coverage now includes Ace-upcard insurance entry, 2:1 insurance payout, losing/declined insurance, multi-seat decision progression and no-duplication through later SPLIT. Insurance stake remains calculation-only until authoritative shared-wallet reservation/debit is wired in Part 10B.
- 2026-10-08 — Part 8B advanced SPLIT complete — normal split hands may now be resplit until a seat reaches a hard maximum of four simultaneous hands; stable tree-style `handId`s plus reindexed `handIndex` values preserve deterministic same-seat action order after each insertion. Double After Split is enabled on any eligible two-card non-Ace split hand and still consumes exactly one card before forced stand/bust. Splitting Aces has dedicated rules: each Ace child receives exactly one card, is immediately stood, cannot HIT/DOUBLE/resplit, and any resulting 21 remains a normal split 21 rather than a 3:2 natural. UI now exposes `RESPLIT`, shows `MAX 4` when the seat cap is reached, distinguishes Ace-split locked hands, supports 3–4 hands in a compact 2×2 seat layout, keeps per-hand results/wagers visible, and includes all copied/doubled stakes in live TOTAL BET. Regression coverage checks DAS, repeated resplits through the four-hand ceiling, wager growth, split-Ace one-card auto-stand/no-natural behavior, and invalid post-HIT/unequal splits. All added split/double stake remains calculation-only until authoritative shared-wallet reservation is wired.
- 2026-10-08 — Part 8A base SPLIT complete — round hands now have stable `handId`, `handIndex` and `splitDepth`, while `activeHandId` becomes the true action cursor and `activeSeatId` remains a derived UI-compatible seat pointer. SPLIT is available only on the active untouched two-card hand when both cards have the same Blackjack value, so ten-value pairs such as `10 + K` qualify. Part 8A performs one split only: it copies the original wager to a second independent hand, consumes exactly one new shoe card for each child hand, keeps both hands under the same seat, and progresses actions as `Hand 1 -> Hand 2 -> next seat`. A two-card 21 created by a split is a normal 21/stand, never a natural Blackjack payout. The UI exposes the real SPLIT button with the additional stake amount, renders split hands as distinct card/total/wager/result panels inside the same seat, highlights the active sub-hand, updates mobile seat status to the active hand, and includes the copied split wager in live TOTAL BET.
- 2026-10-08 — Part 7 in-round DOUBLE complete — the active hand may double only while it is still `PLAYING`, still has exactly its original two cards, and has not already doubled. A successful DOUBLE records an additional stake equal to the current hand wager by doubling the round wager, consumes exactly one shoe card, then forces the hand closed as `STOOD` or `BUST` and immediately advances to the next playable seat/dealer. Settlement uses the doubled wager, TOTAL BET switches to live round-hand wager totals, the table marks doubled hands with `X2`, and the in-round DOUBLE button shows the required additional stake. Shared-wallet affordability/debit is intentionally not applied yet.

Each hand settles separately as `WIN / LOSE / PUSH / BLACKJACK`; normal wins return 2x stake, pushes return stake, natural blackjack returns 2.5x stake, losses return 0. UI enables HIT/STAND during player turns, reveals dealer hole card/final total at completion and exposes `NEXT ROUND`; round-boundary cut-card reshuffle is honored.
