## Product direction
- Single-player blackjack table with exactly five seats. The same player may occupy and play any subset of 1–5 seats simultaneously.
- Desktop visual target is the approved 16:9 premium live-casino mockup: dark green felt, dark leather rail, restrained gold trim, dealer centered behind the table, five seat arc, compact top HUD and integrated bottom betting/action console.
- Mobile will preserve the same table identity in portrait rather than becoming a generic control dashboard.
- `TABLE MIN` exists. There is no `TABLE MAX` label or configured table maximum; the natural affordability ceiling is the player's available shared wallet balance.
- Pre-deal `X2 BET` doubles the selected seat's wager and is distinct from in-round Blackjack `DOUBLE`/double-down.
- Pre-deal controls must support chip placement, last-chip undo, clearing a selected wager, and clear seat state feedback.
- Empty seats expose a clear `TAKE SEAT` / `TAP TO SIT` affordance. Occupied, selected, bet-ready and in-round states are visually distinct.
- Planned rules baseline: 6-deck shoe, ~75% cut-card reshuffle after a completed round, dealer hits soft 17, Blackjack pays 3:2, normal win 1:1, push returns stake. Split/double/insurance rules are implemented in later parts and must remain server-authoritative once backend work starts.
- The shared `shared_wallets` row and root-scoped `game_session` remain the only live wallet/session authorities; Blackjack never creates an independent spendable wallet.

## Current milestones
- 2026-10-08 — Part 5B initial real round complete — new pure `roundState.ts` owns pre-deal readiness plus the first deal. `$0` occupied seats explicitly sit out; any non-zero wager below the `$10` table minimum blocks DEAL; at least one bet-ready seat is required. A DEAL consumes the existing six-deck shoe in deterministic live-table order (participating seats 1→5 first card, dealer upcard, seats 1→5 second card, dealer hole card), preserves each participating seat's wager, detects two-card naturals, skips natural-blackjack hands when selecting the first action seat, and short-circuits player action when the dealer has natural blackjack. `index.ts` now removes all fake/demo cards: before DEAL the table shows no hand cards; after DEAL it renders actual shoe cards/totals, keeps the dealer hole card hidden during normal play, reveals it immediately for dealer natural blackjack, locks all betting/seat controls for the round, and highlights the active seat as `YOUR TURN`. A Blackjack-owned DEAL button/status/readiness UI plus round-state regression tests were added. HIT/STAND remain intentionally disabled until Part 6; wallet debit/server round authority remain later milestones.
- 2026-10-08 — Part 5A Blackjack core complete — new pure `blackjackCore.ts` and `shoe.ts` modules define physical card/rank/suit types, exact Ace soft/hard evaluation, natural-blackjack and bust detection, dealer hit behavior with H17 as the default, a full six-deck/312-card shoe with unique physical card IDs, Fisher-Yates shuffle with injectable RNG, and a 75% cut-card threshold (`234/312`). Crossing the cut card never reshuffles mid-round: it only marks `shufflePending`; `reshuffleBlackjackShoeAtRoundBoundary` performs the replacement shoe after a completed round. Regression coverage checks six-deck composition, shuffle permutation/RNG validation, Ace transitions, natural blackjack, busts, H17, cut-card continuation and round-boundary reset. The pure module defaults may use `Math.random` for local-only work, but the later authoritative backend must inject/own the real RNG and shoe state.
- 2026-10-08 — Part 4B pre-deal wager controls complete — `UNDO`, `CLEAR BET`, and pre-deal `X2 BET` now operate on the selected seat's ordered denomination history. Undo removes exactly the last placed chip and recomputes `SEATED`/`BET READY` when the wager falls below the `$10` minimum; Clear removes only that seat's wager while keeping the player seated/selected; X2 duplicates the exact denomination sequence (for example `[100,25] -> [100,25,100,25]`) instead of merely multiplying a scalar. Zero-bet/empty-seat actions are no-ops and the UI disables invalid controls. No configured table maximum exists. Wallet affordability/server reservation is intentionally deferred to the later authoritative backend/wallet parts.

Desktop and mobile render the same wager state and real denomination-colored chip stack. `UNDO`, `CLEAR BET`, and pre-deal `X2 BET` remain intentionally disabled for Part 4B. No wallet debit/server betting authority is wired yet.
