Evet, şimdi kalan bug çok net: pair mantığı doğru ama görünür 5 hücre ile yukarıdaki gizli stream arasında devamlılık kopuyor.

Senin Bayern örneğinde olması gereken şu:

GÖRÜNEN EN ÜST HÜCRE:  BAYERN   ← çiftin 1. üyesi
--------------------------------
GİZLİ İLK HÜCRE:       BAYERN   ← çiftin 2. üyesi
GİZLİ SONRAKİ:         random   ← yeni grubun 1. hücresi

Yani üstte görünen Bayern aşağı düştüğünde hemen arkasından ikinci Bayern gelmeli. Replit muhtemelen initial 5 hücreyi oluşturduktan sonra pair phase'i sıfırlıyor veya refill için yeni stream başlatıyor.

Bunu Replit'e gönder:

CRITICAL STREAM CONTINUITY BUG — VISIBLE TOP SYMBOL MUST CONTINUE INTO HIDDEN STREAM

The 2-cell logical pairing behavior is now visually close to correct,
but there is still one major continuity bug.

Example:

The TOP visible cell of a column contains BAYERN.

If that BAYERN is the FIRST member of a logical 2-cell normal-symbol group,
then the NEXT hidden incoming symbol directly above the board must be the SECOND member of that same group.

Currently this continuity is being lost.

When the visible top Bayern falls downward,
a random different symbol can arrive from above.

That is WRONG.

==================================================
1. THERE MUST BE ONE CONTINUOUS COLUMN STREAM
==================================================

Initial board generation and tumble refill must NOT be separate streams.

Each column must have ONE continuous logical stream extending above the visible board.

Conceptually:

VISIBLE / HIDDEN boundary does not matter mathematically.

Example continuous stream:

ROW lower...

The hidden Bayern is already part of the same pair.

==================================================
2. DO NOT RESET PAIR PHASE AFTER INITIAL BOARD
==================================================

This is probably the current bug.

After filling the initial 5 visible positions:

DO NOT reset:

pairPhase
pairedBaseSymbol
pairGroupId
streamCursor

The exact pairing state must survive.

If initial board consumption ends after consuming the FIRST member of a pair:

the hidden stream must remain in:

SECOND_MEMBER_PENDING

state.

==================================================
3. BOARD HEIGHT IS 5 — THIS MATTERS
==================================================

The visible column has 5 cells, which is an odd number.

Because normal logical groups are 2 positions:

[A1 A2]
[B1 B2]
[C1 C2]
...

consuming exactly 5 normal stream positions can naturally stop at:

C1

meaning:

C2

must remain immediately above the visible board.

This is EXPECTED behavior.

Do not force pair boundaries to align with the visible 5-cell board.

==================================================
6. NEVER GENERATE REFILL FROM A FRESH PAIR STATE
==================================================

Forbidden behavior:

initialBoardGenerator()
then later:
new RefillGenerator()

or:

resetPairPhase()

when tumble starts.

There is only ONE persistent ColumnStream object for the complete spin / Free Spin sequence.

Refills consume the already-existing stream.

==================================================
7. STORE PENDING SECOND MEMBER EXPLICITLY
==================================================

Use authoritative stream state conceptually like:

ColumnStreamState {
    pairPhase: "FIRST" | "SECOND";
    pairedBaseSymbol: NormalSymbol | null;
    pairGroupId: number | null;
    queue: IncomingItem[];
}

If pairPhase == SECOND:

the next normal stream position MUST resolve the second member rule from the existing pairedBaseSymbol.

Do not generate a new first symbol.

==================================================
8. BETTER: PREGENERATE CONTINUOUS STREAM
==================================================

Preferred implementation:

Before visible consumption, generate a sufficiently long continuous incoming stream for each column.

Example:

50+ incoming positions / packet metadata.

Then:

initial board consumes first 5 visible entries.

Everything above remains untouched.

Tumble refill simply consumes the next entries.

This completely prevents visible/hidden discontinuity.

==================================================
9. DO NOT REBUILD THE QUEUE AFTER INITIAL BOARD
==================================================

Wrong:

generate 5 visible cells
discard generator state
generate refill queue separately

Correct:

generate / maintain one continuous stream

consume 5
leave rest exactly as generated.

==================================================
10. SPECIAL SYMBOLS STILL USE THEIR OWN RULES
==================================================

This continuity rule applies to the normal 8 team symbols.

Scatter and multiplier characters remain independent special symbols.

However they must also occupy real positions in the same continuous incoming stream.

Do not overlay them after generation.

==================================================

A special symbol should NOT be inserted inside an already-started normal pair.

If first normal pair member has been emitted:

BAYERN

resolve that second position BEFORE beginning a new special-symbol opportunity.

In other words:

once a 2-position normal pair group has started,
complete that group atomically.

Do not insert:

BAYERN

That breaks the pair.
