CRITICAL SYMBOL GENERATOR REWORK — TRUE 1x2 STACKED SYMBOL PACKETS

The current “pair probability” implementation still does NOT create the visual behavior I want.

I provided a Sweet Bonanza reference video.

The important visible behavior is:

When replacement symbols fall from above, matching symbols very often appear as a VERTICAL 2-SYMBOL STACK.

Example:

WATERMELON
WATERMELON

They do not feel like two independent cells that randomly happened to match.

They feel like ONE 1x2 SYMBOL PACKET coming from above.

This is the behavior we need.

DO NOT attempt another simple “increase identical-symbol probability” patch.

Rebuild normal incoming-symbol generation around STACK PACKETS.

==================================================
1. STOP THINKING IN INDIVIDUAL CELLS
==================================================

Normal incoming generation must no longer be conceptually:

generate cell
generate cell
generate cell
generate cell

Instead generate PACKETS.

A normal packet can be:

SINGLE PACKET:
[A]

or:

DOUBLE STACK PACKET:
[A]
[A]

The double stack is one generated object with:

symbolType
height = 2
stackId

Example:

{
    symbol: CHELSEA,
    height: 2,
    stackId: 84721
}

The two Chelsea items belong to the SAME generated stack.

==================================================

Important.

Suppose only ONE empty cell exists,
but the next incoming packet is:

Do NOT discard the second PSG.

Do NOT generate another symbol.

Consume only the lower member into the visible board.

Keep:

the second PSG
